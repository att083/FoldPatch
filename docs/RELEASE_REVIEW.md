# 현재 검증 결과

[English](RELEASE_REVIEW.en.md) · [호환성 상세](COMPATIBILITY.md) · [개발 단계별 이력](research/2026-09-20-development-history.md)

## 미배포 alpha.5 · target API 37

2026-09-21 로컬 확인. 후보 버전은 compile/target API 37, 최소 Android 15/API 35를 사용합니다. **Fold3 / Android 15에서 target 37 후보의 업데이트와 핵심 동작을 확인했습니다.** 공개 alpha.4 APK와 그 버전의 GitHub 검사 결과는 그대로입니다.

Fold3의 기존 설치와 서명을 맞추기 위해 release 빌드를 기존 개발용 키로 서명해 업데이트했습니다. 공개용 서명 APK와 앱 내용이 동일함을 확인했으며, 공개용 서명 APK 자체를 폰에 설치한 시험은 아닙니다. 왼쪽 44%·오른쪽 42.5% 범위, 정상 터치 쪽과 자동 켜기 설정을 유지했습니다. 화면 재배치와 범위 설정의 뒤로 가기를 확인했고, 사용자가 터치패드 클릭·스크롤·키보드 입력 및 접기·펼치기 정상 동작을 확인했습니다. 장시간 사용이나 모든 시스템 전환을 재시험한 것은 아닙니다.

- 설정·화면 범위 조정에 최신 뒤로 가기 콜백과 시스템 바 여백 처리를 적용했습니다. 여백은 조작 버튼에만 적용하며 실제 화면 눈금의 기준은 바꾸지 않습니다.
- Android 16·17 가상 기기: 실제 Shizuku 권한 허용·사용 준비, 재배치·비대칭 폭·50%+50%·프로세스/영역 소유권 복구, 포인터 좌표·스크롤·핀치·길게 누르기·키보드 편집, 설정 뒤로 가기·범위 저장/취소/시간 만료·가로 전환 복구를 통과했습니다.
- Android 17에서는 알림·빠른 설정 타일로 설정 열기, 화면 껐다 켜기, 이미 허용한 Shizuku 서버 재시작 후 연결 복구도 통과했습니다. 무선 페어링이나 재부팅 후 Shizuku 자동 시작 시험은 아닙니다.
- Android 15 가상 기기에서는 재배치·복구·50% 전환 검사를 통과했습니다. 공개 서명 alpha.4에서 같은 서명의 alpha.5로 업데이트해 44.5%/45% 화면 범위·준비 완료 상태·Shizuku 권한 유지를 확인했고, 업데이트 후 설정 뒤로 가기·범위 취소도 통과했습니다.
- **Android 14 지원 제외:** 최소 버전을 올리기 전 API 34 AOSP 가상 기기에 설치는 됐지만, 재배치 시험 중 `WindowManagerService.mirrorDisplay` / `nativeMirrorSurface`에서 `system_server`가 종료됐습니다. Android 14는 지원에서 제외하며 새 APK는 Android 15 이상에서만 설치됩니다.
- 호스트 검사·번역 리소스·debug/release 빌드·서명 인증서를 로컬에서 확인했습니다. 추가한 권한은 없습니다. Play Store 심사 통과나 새 GitHub 원격 CI 결과를 의미하지 않습니다.

위 가상 기기 동작 시험은 최소 버전 변경 전에 진행했으며, 하한 변경만을 위해 반복하지 않았습니다. 하한 변경 후 호스트 검사·debug/release 빌드·APK의 최소 API 35와 target API 37·서명·공개 문서 링크를 별도로 확인했습니다.

2026-09-21 추가 비교(최소 버전 변경 전): 공개 alpha.4와 후보 alpha.5의 서명 APK에 들어 있는 화면 처리 코드를 같은 API 34 가상 기기에서 실행했습니다. 두 버전 모두 켜기 → 끄기 → 다시 켜기에서 같은 OS 종료가 재현됐습니다. 따라서 관측한 화면 처리 문제는 기존 공개 버전에도 존재하며 타겟 변경으로 새로 생긴 것은 아닙니다. 삼성 Android 14 실기기에서의 재현 여부는 미확인입니다.

## 공개 alpha.4 검증 기록

대상: **v0.1.0-alpha.4**, 정리일 2026-09-21. GitHub에 배포하는 첫 공개 시험판입니다. **실기기 확인은 삼성 Galaxy Z Fold3 / Android 15 / One UI 7이며, Android 16·17은 가상 기기만 확인했습니다.**

2026-09-21 첫 공개 전에 앱 ID를 `dev.foldpatch`로 확정했습니다. Fold3에 새 개발 APK를 설치하고 기존 화면·조작 설정을 이전했으며, 새 권한은 사용자가 준비 화면에서 허용했습니다. 사용자가 터치패드 클릭·스크롤, 키보드 입력, 접었을 때 외부 화면 복구와 다시 펼쳤을 때 자동 복귀를 확인한 후 이전 앱을 삭제했습니다. 설정을 이전한 시험이며 독립적인 초보자 새 설치 시험은 아닙니다. 아래의 기존 가상 기기·브라우저 설치 기록은 ID 변경 전 결과입니다.

| 최신 50% 범위 | Fold3 설정 화면에서 양쪽 50% 저장·이전 범위 복귀. Fold3/Android 17의 실제 입력 경로로 양끝 좌표·확대·길게 누르기 자동 확인 | 합성 입력 스트림은 손가락 감각이나 손상 패널 시험을 대체하지 않음 |
| Android 15·16·17 가상 기기 | 통합 재배치, 비대칭 범위, 강제 종료·소유권 상실 후 복구. Android 16·17 입력·키보드 편집 | 삼성 화면 구조·물리적 접힘·최신 One UI 실기기는 미검증 |
| 사용 준비 | Android 15·16에서 Shizuku 무선 페어링·권한 거절/재시도·범위 저장·재시작 후 복귀 | 삼성 새 설치와 개발자 도움 없는 초보자 사용성 시험은 남음 |

| 공개 APK | 별도 배포 키로 서명 검증. Android 17 가상 기기의 새 설치·첫 실행 및 업데이트 후 준비 단계 유지 | 기존 삼성 폰은 데이터를 보존하는 개발 서명 업데이트로 확인 |
| 브라우저 설치 | Android 17 가상 기기 Chrome에서 APK 다운로드 → 출처 허용 → Android 설치 → 열기 → 첫 설정 화면. 다운로드 해시·버전·디버깅 비활성 확인 | 로컬 HTTP 서버에서 받은 시험. 실제 GitHub HTTPS 다운로드 및 삼성 새 설치 확인은 아님 |

Android 17은 초기 경로가 실패했지만, 이후 시스템 소유권을 유지하는 대체 경로를 통합해 위 시험을 통과했습니다. 과거 기록의 ‘미지원’ 문장은 당시 단계에 대한 설명입니다. Android 17의 하단 제스처·작업표시줄과 다른 제조사 화면은 여전히 추가 확인이 필요합니다.

## 소스와 배포 파일

- 공개용 ZIP만 별도 폴더에 풀어 테스트 9종·release 검사·221개 문자열 × 6개 리소스 검사와 release 빌드를 통과했습니다.
- 재빌드한 APK와 서명된 후보의 manifest·DEX·리소스·라이선스 등 파일 내용이 일치합니다. 서명과 ZIP 메타데이터를 제외한 비교이며 APK 전체가 바이트 단위로 동일하다는 뜻은 아닙니다.
- release는 디버깅 불가이며 개발 시험 진입점이 제외됩니다. 인터넷 권한이 없고, 고정 의존성 해시와 라이선스를 검사합니다.
- GitHub Actions에 같은 호스트 검사·unsigned release 빌드·공개 파일/문서 링크 검사를 구성했습니다. 워크플로 문법 검사와 공개 소스에서의 동일 명령 실행을 통과했습니다. **[GitHub 원격 검사 통과](https://github.com/att083/FoldPatch/actions/runs/35564666849)**를 2026-09-21 확인했습니다. GitHub에서 빌드한 unsigned APK의 내부 파일 내용도 로컬 후보와 일치합니다.
