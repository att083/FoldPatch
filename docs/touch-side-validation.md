# 정상 터치 쪽 선택 — v0.1.0-alpha.2

## 계약

설정의 **터치가 되는 쪽**은 물리적으로 입력 가능한 쪽이다. 조작바의 **왼쪽 / 오른쪽 / 전체**는 조작 대상 화면이다. 앱 개수나 앱 배치와 관계없다.

| 정상 터치 쪽 | 왼쪽 조작 | 오른쪽 조작 | 전체 조작 |
| --- | --- | --- | --- |
| 왼쪽 | 일반 터치 | 왼쪽 터치패드로 오른쪽 | 왼쪽 터치패드로 양쪽 |
| 오른쪽 | 오른쪽 터치패드로 왼쪽 | 일반 터치 | 오른쪽 터치패드로 양쪽 |

설정·범위 조정·키보드·조작바가 정상 쪽으로 이동한다. 화면 내용은 뒤집지 않으며, 좌우 폭과 기존 앱 배치는 바꾸지 않는다. 조작바 위치는 좌우별로 저장한다. 일반 터치/반대쪽 터치패드의 역할은 전환 후에도 유지하며 전체 모드는 계속 전체다.

변경은 15초 미리보기다. 이동한 쪽에서 ‘이쪽에서 사용할게요’를 누르면 저장한다. 미확인·화면 이탈·서비스/프로세스 재시작은 기존 쪽과 조작 대상으로 복구한다. 기존 설치 기본값은 왼쪽이다.

## 코드 및 자동 시험

- TouchSide: 저장, 여러 번 변경한 미리보기의 원점 복구, 만료, 조작 대상 매핑, 비대칭 영역의 조작바 범위.
- PointerGeometry: 왼쪽/오른쪽의 단일 영역 한계와 전체 영역의 가운데 건너뛰기.
- 기존 한글 조합·삭제, 포인터 감도, 두 축 스크롤, 화면 범위 복구 회귀 시험 통과.
- debug/release 빌드 통과. TouchSideProbeActivity는 debug 소스·manifest에만 포함하고 release DEX에 포함하지 않음을 확인.

## 실기기 확인

SM-F926N / Android 15 / One UI 7에서 기존 데이터 유지 업데이트로 확인했다.

- 오른쪽 선택 후 미확인 시 왼쪽으로 자동 복구. 미확인 변경 중 앱 강제 종료·재실행 시에도 저장된 쪽으로 복구.
- 오른쪽 저장 후 설정 패널·조작바가 오른쪽 가시 영역 안에 배치됨.
- 오른쪽 키보드의 실제 키 위치에 ADB 터치를 보내 `한` 입력 확인. 키보드 전체와 입력칸이 오른쪽에 표시됨.
- 오른쪽에 범위 조정 슬라이더·버튼 표시. 보정하지 않은 물리 화면 양 끝 0% 눈금 유지. 오른쪽 폭을 44.5%에서 44%로 시험 적용한 뒤 취소하여 기존 범위 복구.
- 합성 터치패드 입력 → 실제 서비스 → Binder 주입 → 시험 앱 수신: 오른쪽에서 왼쪽/전체, 왼쪽에서 오른쪽/전체의 네 조합 모두 포인터 이동·클릭·가로 70px/세로 100px 스크롤 통과. 전체 모드는 양쪽 클릭 확인.
- 시험 후 정상 터치 쪽을 왼쪽으로 저장하고 기존 일반 터치 모드로 복원. 기존 화면 범위·감도·조작바 위치와 크기·고정 버튼을 보존.

기기 자체의 오른쪽 디지타이저가 고장 나 있으므로 정상 오른쪽 패널에서의 실제 손가락 입력을 검증했다고 주장하지 않는다. 시험 앱의 synthetic pad stream은 실제 서비스와 Binder 입력 전달·앱 수신을 확인하며, 접근성의 물리 하드웨어 입력 수신을 대신하지 않는다.
