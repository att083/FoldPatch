# 에이전트와 함께 폴드패치 설치하기

[English](AGENT_INSTALL.en.md) · [README](../README.ko.md) · [에이전트 시작 문서](../AGENTS.md)

사용자가 에이전트에게 “이 저장소 보고 내 폰에 설치해 줘”라고 요청했을 때 따르는 안내입니다. 도구와 기존 허용 범위로 할 수 있는 작업은 직접 진행하고, 사용자의 폰 조작이나 판단이 필요한 단계만 요청합니다. 설치 대상은 Android 폰입니다.

## 1. 현재 상태부터 확인하기

[호환성](COMPATIBILITY.md)과 [설치·복구 안내](INSTALL.md)를 읽습니다. 연결된 기기 정보로 확인할 수 있는 내용을 먼저 확인하고, 모르는 것만 사용자에게 묻습니다. 기기·OS, 기존 폴드패치 설치 여부, 에이전트가 실제로 폰에 연결할 수 있는지 파악합니다. 내부 화면에서 터치가 되는 쪽을 모르면 사용자에게 확인합니다.

설치 최소 조건은 Android 14/API 34입니다. 실기기 확인은 폴드3·Android 15이며, Android 16·17은 가상 기기만 확인했습니다. Shizuku가 설치·실행되고 권한을 허용한 상태여야 합니다. 처음 준비는 외부 화면에서 할 수 있고, 화면 범위를 맞출 때는 세로로 펼쳐 잠금을 해제해야 합니다.

| 현재 상황 | 진행할 일 |
| --- | --- |
| 공개된 서명 APK가 있음 | 해당 릴리스의 APK·체크섬을 받아 확인합니다. 일반 설치에 소스 빌드를 먼저 요구하지 않습니다. |
| 아직 공개 전인 개발자 작업 폴더 | 제공받은 로컬 배포 후보의 버전·체크섬·서명 출처를 확인합니다. 공개 다운로드가 있다고 안내하지 않습니다. |
| 설치 가능한 APK가 없음 | 없는 상태를 설명합니다. 사용자가 개발 빌드를 원하면 [빌드 안내](BUILD.md)를 따르되, 개발용 시험 기능과 서명 차이를 설명합니다. 그렇지 않으면 필요한 릴리스 파일을 명확히 알려 줍니다. |
| 폰 연결·조작 도구가 없음 | 확인된 APK 링크를 제공하고 폰 브라우저의 설치 과정을 안내합니다. 직접 설치했다고 말하지 않습니다. |
| 이미 설치했거나 준비 중간에 멈춤 | 기존 데이터와 완료한 단계를 보존하고, 버전과 실제 준비 상태에 따라 이어 갑니다. |

## 2. 설치 파일 선택·확인하기

사용자가 지정한 저장소 또는 확인된 Git 원격 주소를 기준으로 릴리스를 찾습니다. alpha 같은 시험판은 GitHub의 `latest`에 나타나지 않을 수 있으므로 릴리스 목록과 실제 태그를 확인합니다. **`foldpatch-release.apk`와 `foldpatch-release.apk.sha256`가 함께 있는 릴리스**를 선택합니다. 다운로드 주소를 추측하거나 다른 저장소의 APK, unsigned Actions 산출물로 대신하지 않습니다.

GitHub CLI가 있다면 아래 Bash 예시를 사용할 수 있습니다. 두 값은 확인된 저장소와 실제 존재하는 태그로 바꿉니다. 브라우저나 API로 같은 일을 진행해도 됩니다.

```bash
FP_REPO='OWNER/REPOSITORY'
gh release list --repo "$FP_REPO"
FP_TAG='EXISTING_RELEASE_TAG'
gh release view "$FP_TAG" --repo "$FP_REPO" --json tagName,isPrerelease,assets,url
FP_DOWNLOAD_DIR="$(mktemp -d)"
gh release download "$FP_TAG" --repo "$FP_REPO" \
  --pattern foldpatch-release.apk --pattern foldpatch-release.apk.sha256 \
  --dir "$FP_DOWNLOAD_DIR"
```

체크섬 파일이 APK 이름에 대한 SHA-256 한 줄인지 먼저 읽어 확인합니다. 절대 경로나 상위 폴더 경로가 있으면 그대로 검사 명령에 넘기지 않습니다.

```bash
(cd "$FP_DOWNLOAD_DIR" && sha256sum --check foldpatch-release.apk.sha256)
```

체크섬 일치는 파일이 바뀌었는지 확인하는 수단이며 배포자 신원의 독립적인 증명은 아닙니다. SDK 도구가 있다면 `aapt2 dump badging`으로 패키지·버전을, `apksigner verify --verbose --print-certs`로 서명을 확인합니다. 선택한 릴리스의 서명 기록과 비교하고 기존 설치와 업데이트 가능한지도 확인합니다. 설치하려는 사용자에게 배포용 비밀 서명 키를 요구하지 않습니다.

## 3. 가능한 경로로 설치하기

**폰에서 설치:** 확인한 릴리스의 APK를 브라우저에서 받아 엽니다. Android가 해당 브라우저·파일 앱에서 설치하도록 허용할지 물으면 의미를 설명하고 사용자가 결정하게 합니다. 제조사별 제한은 다를 수 있습니다. 설치를 강행하려고 기기 보호 기능을 전반적으로 끄라고 안내하지 않습니다.

**이미 허용된 컴퓨터 연결로 설치:** Android SDK platform-tools의 `adb devices -l`로 연결 상태를 확인합니다. 대상 폰을 명확히 고르고 모든 기기 명령에 `-s`를 씁니다. 여러 폰·가상 기기가 보이거나 어느 기기인지 불분명할 때만 대상을 확인합니다. WSL·원격 환경에서는 컴퓨터에 보이는 폰을 에이전트가 직접 못 볼 수 있습니다. 공유 ADB 서버를 초기화하지 말고 이미 작동하는 연결 경로를 활용합니다.

컴퓨터 무선 ADB 연결이 필요하면 [Android 공식 안내](https://developer.android.com/tools/adb#connect-to-a-device-over-wi-fi)를 따릅니다. 페어링 포트와 연결 포트는 다르며 바뀔 수 있습니다. 사용자가 디버깅을 허용하고 가능하면 직접 코드를 입력하게 합니다. 코드를 스크립트·로그·이슈에 보관하지 않습니다. **컴퓨터와의 ADB 페어링은 Shizuku의 페어링·시작과 별개입니다.**

아래 예시의 대상은 확인된 기기 식별자로 바꿉니다. 값이 없다고 임의의 첫 기기를 사용하면 안 됩니다.

```bash
FP_DEVICE='SELECTED_DEVICE_SERIAL'
adb -s "$FP_DEVICE" shell getprop ro.product.model
adb -s "$FP_DEVICE" shell getprop ro.build.version.sdk
adb -s "$FP_DEVICE" shell pm path dev.reachpad
```

이미 설치돼 있다면 먼저 설치된 버전을 확인합니다. 사용 중인 폴드패치를 업데이트할 때는 앱 설정에서 끄고 일반 화면·키보드로 복귀할 시간을 줍니다. 선택한 APK를 설치할 수 있는 상태가 되면 진행합니다.

```bash
adb -s "$FP_DEVICE" install --no-incremental -r "$FP_DOWNLOAD_DIR/foldpatch-release.apk"
adb -s "$FP_DEVICE" shell am start -n dev.reachpad/.NativeActivity
```

`-r`은 호환되는 업데이트에서 데이터를 유지합니다. 서명 불일치나 버전 다운그레이드 오류가 나면 맞는 APK를 찾아야 합니다. 앱 삭제·데이터 초기화·패키지 이름 변경·강제 다운그레이드로 해결하지 않습니다. `scripts/run-device.sh`는 **debug APK**를 설치하므로 공개 릴리스 설치에 사용하지 않습니다. 구형 실행 화면이나 개발용 연결·시험 진입점으로 사용 준비를 대신하지 않습니다.

## 4. 폰에서 필요한 준비 이어 가기

앱의 **사용 준비** 흐름을 사용합니다. 자세한 메뉴 이름은 [설치 안내](INSTALL.md)를 따르고, shell 명령으로 시스템 설정을 써서 동의·준비 절차를 건너뛰지 않습니다.

| 에이전트가 할 일 | 사용자에게 필요한 일 |
| --- | --- |
| Shizuku 공식 설치·시작 경로를 찾고 현재 필요한 단계만 설명 | 설치·시작, 무선 디버깅·페어링·폴드패치 권한 허용. 페어링 코드는 Shizuku의 안내에 입력 |
| 화면 표시·접근성·키보드 권한의 용도 설명 | Android와 폴드패치에서 권한·동의 여부 결정 |
| 화면 범위 맞추기 열기 또는 위치 안내 | 실제 터치가 되는 쪽과 보이는 폭 판단. 슬라이더·±로 조절하고 미리보기·저장 |
| 커서 이동·클릭·스크롤·키보드 사용법 안내 | 실제 손가락으로 조작해 손상된 화면에서도 쓸 수 있는지 확인 |

**스크린샷에 전체 화면이 보인다고 양쪽 50%로 설정하지 않습니다.** 패널의 실제 손상은 일반 스크린샷에 나타나지 않습니다. 범위 눈금은 보정하지 않은 화면의 양 끝에서 각각 0%로 시작하며, 각쪽은 20~50%를 선택할 수 있습니다. 양쪽 50%면 원래 전체 화면을 유지합니다. 기존에 저장된 범위는 사용자가 변경하려는 경우에만 조정합니다.

Shizuku가 종료된 경우와 살아 있는 서비스에 다시 연결하는 경우를 구분합니다. 비루팅 재부팅 후에는 Shizuku가 종료되며, 다시 연결하려고 폴드패치 설정을 지울 필요는 없습니다. 복구 방법으로 공용 Wi-Fi를 요구하지 않습니다. 컴퓨터 ADB 연결만 끊긴 것을 폰 안의 폴드패치 연결 실패로 단정하지 않습니다.

## 5. 설치에 필요한 만큼 확인하고 마무리하기

설치된 버전과 폴드패치 실행을 확인합니다. 사용 준비를 끝내거나 남은 단계를 정확히 알려 줍니다. 폰이 준비됐다면 평소 앱 화면, 커서 클릭·스크롤·키보드, 접기 또는 끄기 후 기본 화면 복귀를 사용자에게 확인받습니다. 설치 완료를 위해 재부팅·Shizuku 종료·네트워크 차단·개발 시험 화면을 강제로 실행하지 않습니다.

마지막에는 **설치한 버전·출처 / Shizuku·사용 준비 상태 / 실제 확인한 내용 / 남은 한 단계**를 짧게 보고합니다. “APK를 받음”, “설치함”, “준비를 끝내 실제 조작 확인함”을 구분합니다. 직접 볼 수 없었다면 사용자에게 확인받은 결과임을 명시하고, 페어링 코드·개인 화면·검토하지 않은 시스템 로그는 보고에 넣지 않습니다.
