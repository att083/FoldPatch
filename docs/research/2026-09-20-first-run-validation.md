# 첫 사용 준비 흐름 검증 · 2026-09-20

## 환경과 범위

기존 사용자 기기와 분리된 새 Android 15 가상 기기에서 FoldPatch alpha4 debug의 첫 실행을 확인했다. Google APIs x86_64 시스템 이미지 revision 9, Android Emulator 37.1.11, 1768 × 2208 / 420 dpi를 사용했다. Shizuku는 [공식 다운로드](https://shizuku.rikka.app/download/)가 연결하는 공식 GitHub의 13.6.0.r1086.2650830c APK다.

두 APK의 설치는 시험용 ADB로 진행했다. 이후 Shizuku의 실행은 ADB 시작 스크립트로 대체하지 않고, 시스템 무선 디버깅 페어링 화면과 Shizuku 알림의 코드 입력·시작 버튼을 사용했다. 권한 허용도 실제 Android UI에서 처리했다. 기존 Fold3의 앱 데이터·설정·Shizuku 권한은 변경하지 않았다.

## 발견한 문제와 수정

1. **개발자 옵션을 켜지 않아도 다음 단계로 이동할 수 있었다.** 다음 버튼과 개발자 옵션 열기에서 실제 활성화 상태를 확인하도록 수정했다. 꺼져 있으면 첫 안내와 필요한 행동을 표시한다. 수정 후 새 가상 기기의 비활성 상태에서 안내가 표시되고 단계가 유지되는 것을 확인했다. 활성 상태에서는 다음 안내로 진행했다. 제조사가 해당 상태 읽기를 제한한 경우에는 수동 안내 경로를 유지한다.
2. **연습 안내의 버튼 이름이 실제 버튼과 달랐다.** 영어의 Whole/All 등 불일치를 없애고 실제 ‘전체’ 버튼의 번역 리소스를 설명에도 사용한다.
3. **페어링 준비 중 오래 머무르면 Shizuku 알림이 사라질 수 있었다.** 시험 중 Shizuku 페어링 서비스의 시간 제한을 만났다. Shizuku에서 페어링을 다시 열어 성공했으며, 이 복구 방법을 앱의 페어링 설명과 설치 문서에 추가했다.

수정 문자열은 기본값·영어·한국어·일본어·중국어 간체/번체에 반영했다. 226개 키 × 6개 리소스의 누락·형식을 검사하고 debug와 unsigned release APK를 빌드했다. 공개용 소스 묶음에는 이 기록을 포함하고, 시험 화면·상세 로그·페어링 정보는 포함하지 않는다.

## 아직 확인하지 않은 것

- 브라우저에서 APK를 내려받아 ‘이 출처 허용’과 패키지 설치 화면까지 진행하는 전체 다운로드·설치 경로. 이번에는 APK를 ADB로 설치했다.
- 아무것도 준비되지 않은 실제 삼성 One UI 기기의 최초 설정. 가상 기기 결과는 삼성 메뉴·보호 설정·다른 기기의 호환성을 보장하지 않는다.
- 처음 접하는 일반 사용자가 도움 없이 안내를 이해하고 마칠 수 있는지에 대한 사용성 시험.
- 물리적인 화면 손상, 접기·펼치기, 외출 중 연결 유지 등 이번 첫 사용 준비와 별개의 시험.

따라서 이 결과는 **새 Android 환경에서 안내와 실제 권한·페어링·완료·복귀 흐름이 동작했다는 검증**이다. 모든 기기에서 누구나 막힘 없이 설치할 수 있다는 인증은 아니다. 이번 수정 APK는 가상 기기에만 설치했다.

## 안내 문구 검토 후 수정

사용자 검토를 반영해 첫 화면을 ‘쓸 수 있는 화면을 이어붙여 볼까요?’로 바꾸고, 설치·권한 설정은 바깥 화면에서 진행할 수 있으며 화면 범위를 맞출 때부터 내부 화면이 필요하다고 구분했다. 코드의 외부 화면 전체 폭 배치와 RANGE 단계의 내부 화면 조건을 확인했다. 이번 문구 수정에서는 실제 접기 동작을 다시 시험하지 않았다.

준비·재연결·연습·범위 안내의 32개 문구를 각 리소스에 반영했다(기존 27개 수정, 제목·재시작 안내 5개 추가). 개발자 옵션·무선 디버깅·페어링 단계마다 필요한 행동을 제목으로 표시하고, 준비 완료 후 Shizuku가 꺼진 경우에는 다시 시작하는 방법과 저장된 범위·설정이 유지된다는 안내를 보여준다. 권한 허용 및 범위 저장의 판정 로직은 변경하지 않았다. 별도의 접근성·키보드 동의 설명도 유지했다.

231개 문자열 × 6개 리소스 검사와 debug 빌드를 통과했다. 별도 Android 16 가상 기기에서 안내 화면을 다시 촬영해 로컬 HTML 자료에 반영했다. 이번 촬영에서는 이미 페어링한 Shizuku를 다시 시작하고 시험 기기의 앱 데이터·권한 상태를 조절해 필요한 안내를 표시한다. 무선 페어링부터 새로 검증하는 시험과 구분하며 사용자의 기존 폰에는 설치하거나 설정을 변경하지 않는다.

완료 후 안내의 하단 버튼은 ‘뒤로’ 대신 ‘설정으로 돌아가기’로 구분했다. 마지막 연결 복구 화면의 촬영 상태를 만들 때는 Shizuku가 표시한 공식 컴퓨터 시작 명령을 시험용 ADB로 실행했다. 이번 문구 검토가 무선 재시작 안정성을 새로 검증한 결과라는 뜻은 아니다.
