## 검증 기록

- Java 단위 시험: 한글 조합·삭제, 포인터 영역 경계/속도, 상하·좌우 스크롤 변환, 범위 저장·취소·만료·복구 통과.
- release manifest 검사: 디버깅 비활성, 시험 진입점 제외, 최소 API·버전, 인터넷 권한 없음, 고정 의존성 해시 확인 통과.
- debug/release APK 빌드 성공. compile-only annotation / Java source-target 관련 기존 경고 있음.
- 기존 실기기 사용자 확인: 양쪽 클릭·양방향 스크롤, 조작바, 포인터 속도, 키다운 진동, 범위 눈금, 최근 앱 제스처, 알림창 클릭·스크롤, 원래 앱의 접기/펼치기 연속성. 이 항목은 개발 과정의 누적 확인이며 모두 이번에 재시험한 것은 아님.
- 최종 release manifest의 non-debuggable APK를 기존 개발 키로 서명하여 SM-F926N에 덮어 설치: 실행, Shizuku 연결, 1574px 앱 재배치, 새 안내 화면 스크롤 확인. 기존 데이터를 지우지 않기 위한 시험 서명이며 공개용 서명과 다릅니다.
- release 빌드의 ProbeActivity 직접 실행은 Activity does not exist로 거부됨. 패키지 flags에 DEBUGGABLE 없음.
- 폴드패치 끄기와 앱 force-stop에서 reflow journal 제거, 삼성 기본 키보드 복구 확인. 수동 재실행 시 폴드패치 복귀 확인.
- 최종 개발 빌드로 되돌린 뒤 범위·이전 범위·속도·조작바 크기·방향·버튼·위치·모드·자동 시작 등 기존 사용자 설정 14개가 설치 전과 동일함을 확인. 새 사용 준비 확인값만 추가.
- 초기 설정 안내와 최종 홈 화면을 실제 화면 캡처로 확인. 개인 기기의 캡처·로그는 공개 묶음에 포함하지 않음.
- 공개 소스 폴더만으로 시험과 release 재빌드 통과. 원본 release와 ZIP 내부 모든 파일 내용이 같음. APK 안의 프로젝트·외부 라이선스 고지 확인.
- 별도 RSA 3072 배포 키로 공개 후보 APK 서명 후 apksigner 검증 통과. 키·암호는 로컬 비공개 보관. 이 새 서명의 APK를 깨끗한 기기에 설치하는 시험은 아직 안 함.
- APK 서명 인증서 SHA-256: `c069f52970619a240dab85e4e519ae59c82cd03ca1a5ccfb0ac6e3fb161c0e48`.

기기 UI 계층 수집 도구는 접근성 서비스를 일시 중단시킬 수 있어, 최종 실행 상태는 계층 수집을 종료한 뒤 화면 캡처와 reflow 기록으로 확인했습니다. 자동 도구로 클릭한 것은 사용자 손가락 조작 재검증과 구분합니다.

## 후속 검증과 기능 제한

다른 기기·Android 버전, 통화·보안/보호 화면·일부 고정 폭 팝업, 재부팅 직후 복구, 장시간 배터리·발열, 다른 접근성 서비스와의 상호작용은 검증이 더 필요합니다. 내부 화면 판별은 현재 물리 크기 기준이라 다른 대화면 기기를 정확히 판별한다고 볼 수 없습니다.

키보드 전체 암호 기호·이모지 지원, 설정 내보내기/가져오기, 가로 화면은 미구현입니다. 길게 누르기·드래그·핀치는 9월 20일 구현했으며 아래 후속 점검을 참조합니다. 키보드의 입력 종류별 최적화와 넓은 문자 지원은 일상 사용 완성도를 높이는 후속 과제입니다.

화면 읽기 기능과 동시 사용은 지원하지 않습니다. 화면 읽기 기능 활성화를 감지하면 실제 터치 캡처와 폴드패치를 해제합니다.

## 2026-09-20 접기 복구와 다음 과제

접은 뒤 상태 표시줄·알림창이 화면 밖에 남고 입력을 가로막는 실기기 오류를 복구했습니다. 화면 정리 순서를 바꾼 뒤 반복 접기·외부 화면 켜기와 사용자 제스처 확인을 통과했습니다. [원인과 검증 기록](2026-09-20-fold-system-ui-restore.md)을 참조하세요.

현재 우선순위와 미검증 항목은 [남은 과제](../BACKLOG.md)에 정리합니다. 자동 재연결·드래그·핀치·좌우 터치 선택은 이미 구현된 기능입니다. 과거 연구 문서의 구현 제안을 현재 미구현 목록으로 해석하지 않습니다.

## 2026-09-20 집 안 안정성 시험

제어 프로세스 종료 후 재연결, 약 120초 Wi-Fi·무선 디버깅 끊김 중 실제 클릭, 약 1분 화면 끄기 후 복귀, 복구 프로세스가 멈춘 상태에서 앱 종료 및 접기 시험을 진행했습니다. 복구 프로세스의 종료 확인과 재시도를 보강한 최종 개발 빌드를 설치했고, 사용자가 외부 화면의 상태 표시줄·홈·최근 앱 제스처를 확인했습니다. 단위 시험과 debug/release 빌드도 통과했습니다.

삼성 작업표시줄의 자동 숨김 상태가 어긋난 현상은 설정을 재적용해 복구했으나 원인은 미확정입니다. 외출·장시간 대기·실제 재부팅과 새 설치는 이번 검증 범위가 아닙니다. 조건과 근거는 [집 안 안정성 시험](2026-09-20-home-stability.md)에 기록합니다. 기존 공개 서명 APK는 이번 수정이 포함된 배포본으로 간주하지 않습니다.

## 2026-09-20 조작바 상태 유지와 키보드 편집

조작바의 세 단계 중 마지막 상태를 저장하고 설정 화면 왕복·서비스 재생성 뒤에 복원합니다. 확장 시 화면 경계 때문에 임시로 이동한 위치는 저장한 위치를 덮어쓰지 않으며, 다시 접으면 복원합니다. 실기기에서 하단·오른쪽 경계에 놓은 작은 손잡이의 앱 강제 종료/재실행, 펼침에 따른 좌우·상하 경계 보정, 설정 왕복, 다시 접기 후 위치 복원을 확인했습니다.

키보드에 접을 수 있는 편집 도구 두 줄을 추가했습니다. 실제 Android 입력칸과 FoldPatch IME를 연결한 개발용 시험에서 전체 선택·복사·잘라내기·붙여넣기, 이모지를 건너는 좌우 이동, 조합 중인 한글의 확정과 편집 후 삽입을 통과했습니다. 시험에 사용한 클립보드는 시험 전 내용으로 복원했고 입력 내용은 로그에 기록하지 않았습니다. 키보드의 닫힌/펼친 도구 배치는 기기 화면 캡처로 확인했습니다. 다른 앱의 자체 입력기나 웹 입력칸 동작은 이 네이티브 입력칸 시험만으로 보장하지 않습니다.

Java 시험, 179개 문자열의 6개 리소스 세트 검사, release 진입점 검사와 debug/release 빌드를 통과했습니다. 편집 시험 화면은 debug에만 포함됩니다.
## FoldPatch 브랜딩 변경 · 2026-09-20

v0.1.0-alpha.4에서 사용자 표시 이름을 FoldPatch(한국어: 폴드패치)로 변경했습니다. 첫 화면·키보드·접근성 서비스·알림·빠른 설정 이름, 설치 및 배포 안내를 함께 갱신했습니다. 임시 아이콘의 교체 방법은 [브랜드 가이드](../BRAND.md)에 있습니다.

기존 개발 APK 위에 같은 키로 업데이트했고 저장된 설정 파일의 값은 모두 동일했습니다. 패키지·컴포넌트·권한 식별자는 유지했습니다. 실기기 설정 화면에서 이름과 문구를 확인했고, 접근성 서비스의 새 이름과 바인딩, 키보드 ID 유지, 알림 제목과 채널 이름도 확인했습니다.

기존 호스트 테스트, release manifest 검사, 182개 문자열 × 6개 리소스 디렉터리 검사를 통과했습니다. 실기기 언어 검사도 11개 언어 선택 사례·2,002개 문자열·264개 조작바 배치를 통과했습니다. debug 및 unsigned release APK를 빌드했고 새 이름의 공개 소스 ZIP을 생성했습니다. 공개 배포나 release 서명은 수행하지 않았습니다. 아이콘은 사용자 요청에 따라 임시로 유지하며 최종 디자인 승인을 받은 상태가 아닙니다.

## Shizuku 연결 확인 안내 수정 · 2026-09-20

연결 확인 버튼의 일괄 권한/폴드패치 시작 안내를 제거했습니다. 연결·권한 필요·서버 실행 필요·연결 중·재시도 지연을 구분하며, 사용 준비와 도움 화면의 상태 설명을 주기적으로 갱신합니다. 연결 확인은 폴드패치나 자동 시작 설정을 변경하지 않습니다. 정상 연결 확인 피드백은 손상 구간에 걸리는 시스템 Toast 대신 버튼 위의 정상 영역에 표시합니다.

기존 Java 테스트·release 검사와 6개 언어 리소스 검사를 통과했고 debug/release 빌드를 생성했습니다. 현재 연결된 기기에서 연결 확인 버튼 동작과 설정 값 보존을 확인했습니다. 미설치·권한 거절·Shizuku 종료·연결 지연 분기는 코드로 검토했으며 이번 확인을 위해 실기기의 실행 중인 Shizuku나 권한을 강제로 해제하지 않았습니다.

첫 실행은 정상 터치 쪽 선택 → Shizuku 설치·실행·허용 → 다른 앱 위에 표시 → 접근성·키보드 개별 동의 → 범위 저장 → 로컬 연습·시작으로 진행합니다. 완료한 준비는 저장하지만 Shizuku 실행·연결·권한과 overlay 권한은 매번 실제 상태로 판정합니다. 설치·페어링을 대신하거나 코드를 수집하지 않습니다. 기존 설정은 새 준비 상태 키만 추가해 유지합니다.

검증: SetupFlowTest에서 중간 재시작, 기존 설치 마이그레이션, 권한 취소, 재연결 뒤 진행 복귀를 확인했습니다. 당시 추가 문자열 포함 225개 키 × 6개 리소스의 누락·형식을 확인했습니다. 기존 SM-F926N에 덮어 설치해 재설치 안내 없이 완료 화면으로 이동하는 동작과 기존 설정값 보존을 확인했습니다. Shizuku 권한 취소·재페어링이나 앱 데이터 초기화는 하지 않았습니다.

## 새 설치 환경 후속 검증 · 2026-09-20

별도 Android 15 가상 기기에서 실제 Shizuku 무선 페어링·시작, 권한 거절과 재시도, 개별 동의, 범위 저장·연습·완료, 중간 재실행과 Shizuku 재시작 후 복귀를 확인했습니다. 개발자 옵션 활성화 확인을 추가하고, 연습 안내의 버튼 이름과 페어링 알림 복구 안내를 수정했습니다. 수정 후 226개 문자열 × 6개 리소스 검사를 통과했습니다. [시험 범위와 결과](2026-09-20-first-run-validation.md)를 참조하세요.

APK는 시험용 ADB로 설치했습니다. 브라우저 다운로드부터의 수동 설치, 실제 삼성 새 설치 및 초보 사용자 사용성 시험은 남아 있습니다. 이번에는 기존 사용자 폰을 변경하지 않았습니다.

## 최초 준비 화면 자료와 Android 16·17 확인 · 2026-09-20

실제 가상 기기 화면 27개를 순서대로 넘기고 확대할 수 있는 로컬 자료 `build/onboarding-review/index.html`을 만들었습니다. 주요 화면은 Android 16에서 한국어 앱으로 새로 촬영했고 페어링 성공 알림 한 장은 앞선 Android 15 화면을 사용했습니다. 각 장에 출처를 표시했습니다. APK 설치는 ADB로 진행했으므로 브라우저 다운로드·APK 설치 UI를 촬영한 자료가 아닙니다. 자료는 별도 로컬 검토 산출물이며 공개 소스 허용 목록에는 넣지 않았습니다.

Android 16에서 화면 버퍼 생성자 제거로 시작 실패를 발견해 공통 생성자와 `update()` 호출로 수정했습니다. 실제 Shizuku 페어링·권한·개별 동의·범위 저장·연습·완료, 입력 좌표·스크롤·핀치·길게 누르기·키보드 편집·종료 복구·Shizuku 재시작 후 복귀를 확인했습니다. 확대 입력 시험은 AOSP의 32 mm 최소 인식 간격을 충족하도록 시험 동작만 보완했습니다. 수정된 출력 경로는 Android 15 가상 기기에서도 실제 시작·표시·종료·복구를 통과했습니다.

Android 17은 Shizuku 실행·권한·개별 동의까지 진행하지만 화면 재배치 시작이 차단됩니다. 시스템이 기존 재배치 대상 영역을 이미 관리하며, 재부팅 후 앱과 UI 시험 도구를 실행하기 전에도 같은 상태였습니다. AOSP 공식 소스에서 새 시스템 조직자 등록을 확인했습니다. **현재 Android 17 지원 완료가 아니며 별도 재배치 경로가 필요합니다.** 소유권 보호 검사를 제거하지 않았습니다. 근거와 환경별 범위는 [호환성 기록](../COMPATIBILITY.md)에 정리했습니다.

debug/unsigned release 빌드, 226개 문자열 × 6개 리소스 검사, release 검사와 변경 내용의 공백 검사를 통과했습니다. 기존 폰에는 이번 수정본을 설치하지 않았습니다. 최신 삼성 One UI 8·9 실기기 시험도 아직 수행하지 않았습니다.

## Android 17 대체 경로 가능성 확인 · 2026-09-20

별도 실험 APK에서 시스템 소유권을 유지한 앱 폭 재배치·상태 표시줄·알림창 표시와 좌우 정상 터치 설정의 클릭·스크롤·키보드 편집을 확인했습니다. 양 끝 좌표, 실제 확대 인식과 길게 누르기도 통과했습니다. 정식 코드 통합이나 삼성 실기기 지원 완료는 아닙니다. 실험 코드는 로컬에 격리했으며 기존 사용자 폰과 배포 APK는 변경하지 않았습니다. [환경·한계·남은 통합 작업](2026-09-20-android17-feasibility.md)을 참조하세요.

## Android 15·16·17 재배치 경로 통합 · 2026-09-20

Android 17 실험 경로를 앱의 정식 소스에 통합했습니다. `ReflowPolicy`는 실제 영역 구조와 점유 상태를 확인해 기존 재배치와 공통 부모 재배치를 선택합니다. `AreaOrganizer`의 Binder 알림으로 영역 추가·소유권 상실을 감지합니다. 다른 조직자가 가져간 영역은 다시 변경하지 않고 복구 기록을 보존해, 영역이 해제된 뒤 복구합니다. 경로를 기록하는 v2 복구 형식과 기존 3개 숫자 형식 읽기, 복구 프로세스 중복 실행 방지 잠금을 추가했습니다.

호스트 테스트에 구조 불일치·점유·기존 복구 기록 검증을 추가했습니다. 가상 기기 검증은 `tests/device/ReflowIntegrationProbe.java`와 기존 입력·키보드 시험을 사용합니다. Android 15·16·17 모두에서 기본/비대칭 범위 재배치, 실제 복구 프로세스 SIGKILL 후 원복, 시험 조직자가 소유권을 가져갔을 때 보존 및 반납 후 복구를 통과했습니다. Android 16은 통합 APK로 기존 클릭·스크롤·양 끝 좌표·확대·길게 누르기·키보드 편집 시험도 다시 통과했습니다. Android 17에서는 통합 APK로 양쪽 터치패드, 입력 좌표·확대·길게 누르기, 양쪽 키보드 편집, 화면 끄기·켜기·앱 강제 종료 복구도 확인했습니다.

실기기 검증 이력은 **삼성 Galaxy Z Fold3 / Android 15 / One UI 7**이며, **Android 16·17 실기기에서는 아직 테스트하지 못했습니다.** 이번 통합 변경은 가상 기기로 검증하며 기존 사용자 폰에는 설치하지 않았습니다. README, 설치 안내, 릴리스 안내, 앱의 사용 준비 설명 6개 리소스에 같은 범위를 명시했습니다. 공개 배포나 release 서명은 하지 않았습니다.

통합 후 호스트 테스트 9종, release 검사, 231개 문자열 × 6개 리소스 검사, debug/unsigned release 빌드를 통과했습니다. release DEX에는 통합 구현이 포함되고 가상 기기용 `ReflowIntegrationProbe`는 포함되지 않음을 확인했습니다. 로컬 공개 소스 묶음도 최신 소스로 갱신했습니다.

## 2026-09-20 — 50% 범위와 설치용 APK

각쪽 최대 폭을 50%로 확장했습니다. 양쪽 50%에서는 원래 화면을 유지하고 포인터·입력 전달만 사용합니다. 화면 재배치 프로세스, 미러 버퍼, 가운데 검은 구간, 시스템 UI 축소를 생성하지 않습니다. 가운데 구간이 있는 설정은 기존 처리와 복구를 사용합니다.

이번 변경에 관련된 확인만 진행했습니다.

- `RangePreviewTest`: 50% 저장·취소·시간 만료·이전 범위 복원, 한쪽만 50%인 설정.
- `PointerGeometryTest`: 가운데 간격 0일 때 좌표 연속성, 양끝과 대상 영역 경계.
- Android 17 가상 기기 `FullWidthIntegrationProbe`: 전체 폭에서 시스템 화면 영역 소유권과 원래 크기 유지, 반복 시작·종료, 손상 구간이 있는 범위 및 한쪽 50%와의 전환·복구.
- Android 17 가상 기기와 **Galaxy Z Fold3 / Android 15**의 `InputIntegrityProbeActivity`: 양끝 클릭 좌표, raw/local 좌표 일치, 확대 인식과 길게 누르기. 앱의 실제 터치패드·입력 전달 경로에 시험 이벤트를 넣는 자동 확인이며 물리 손가락 시험을 대신했다고 주장하지 않습니다.
- Fold3: 실제 범위 설정 화면의 양쪽 슬라이더로 50% 선택·미리보기·저장 확인. 시험 후 기존 44.5% 범위와 조작 설정·이전 범위 기록 복구.
- 최신 release APK를 기존 배포 키로 서명하고 서명 검증 통과. Android 17 가상 기기에서 **서명된 공개 후보 APK의 새 설치·첫 실행과 업데이트 후 준비 단계 유지** 확인. 디버깅 비활성 확인. 삼성 폰에는 기존 데이터를 유지하는 개발 서명 업데이트를 설치했습니다.

README·설치 안내를 APK 다운로드 중심으로 정리하고, 프로젝트 규모를 강조하던 문구를 삭제했습니다. 설치용 APK·SHA-256·공개 소스 ZIP을 로컬 배포 묶음으로 준비했습니다. GitHub 저장소 생성·게시와 브라우저에서 APK를 받아 설치하는 전체 흐름은 아직 수행하지 않았습니다. Android 16·17 실기기 미검증 범위는 유지합니다.
